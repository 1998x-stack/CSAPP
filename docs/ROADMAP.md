# CSAPP 分阶段改造路线图

基准：Computer Systems: A Programmer's Perspective（第三版）。本计划采用“**保留现有知识资产 → 保障安全与准确性 → 完善实践 → 建立长期维护机制**”的顺序。未完成的模板不能算已完成的教材实验。

## 实施原则

- 每模块通过独立 Pull Request 交付，除非人工合并，不直接修改 main。
- 禁止生成脚本覆盖手写笔记、已实现代码或 README。
- 优先保证理论和代码正确性，再扩大实验覆盖率。
- 核心实验以 C / x86-64 / Linux 为主，C++ 和 Python 用于对照与工具。
- 新的实验应提供可重复测试；尊重第三方教材与实验的版权和授权。

## M01 交付说明与验证

不需要先改动已有 12 章。脚本默认只做 dry-run：

```bash
python -m unittest discover -s tests -v
python main.py                    # 预览缺少的章节模板，不写文件
python main.py --apply            # 仅创建缺失的模板，原文件保持不变
python main.py --index            # 预览可选 COURSE_INDEX.generated.md
python main.py --index --apply    # 缺失时创建上述索引，不覆盖原 README
bash modify_files.sh              # 只预览 Markdown 中的数学分隔符变更
bash modify_files.sh --diff       # 预览详细差异
bash modify_files.sh --apply      # 显式转换 Markdown，逐文件留 .bak
```

转换器不再自动清除中文书名/引用括号或其他正文，只替换明确的 LaTeX 数学分隔符。它不会修改源代码、HTML、PDF 或符号链接。若同名 .bak 已存在，则拒绝再次写入该文件；可以先检查备份再决定下一步。

**回滚**：M01 在独立分支上，合并前可直接关闭 PR；已合并则可 revert 对应提交。个别 Markdown 若通过 --apply 转换，可从同目录的 .bak 文件恢复。首次运行或迁移前建议检查 `git status`。
