# M05：全量知识文档、章节导航和审查状态

## 目标与范围

严格使用 M04 的 `curriculum/catalog.json` 作为唯一编号映射：12 章共 378 项，加附录 A 的 2 项，合计 **380 个编号**。所有编号都有文档页面。

- 310 个已有四文件知识点：基于原有 Markdown 动态生成可阅读页面，展示代码、讲解和测试状态。
- 55 个父节目录：生成目录页并列出直属子条目；它们**不是**独立讲解已经完成的证据。
- 15 个缺失的教材编号：生成明确标记的占位页；不伪造笔记、实验或总结。
- 4 份额外资源：在进度页中保留原文件链接，不计入 380 个独立编号。

## 本地使用（按顺序）

要求 Python 3.11+，MkDocs 1.6+ 和 Material 主题。

```bash
python3 scripts/build_curriculum.py --check     # 先校验 M04 全量清单
python3 -m unittest discover -s tests -p 'test_m05_*.py' -v
python3 scripts/build_docs.py                   # 默认只读：统计将生成的文件
python3 scripts/build_docs.py --generate        # 显式写入 build/m05-docs/（非源码目录）
python3 scripts/build_docs.py --verify-generated
python3 -m pip install 'mkdocs>=1.6,<2' 'mkdocs-material>=9.5,<10'
mkdocs build --strict
mkdocs serve
```

构建产物：`build/m05-docs/`（生成的 Markdown 页面和 `metadata/status.json`）与 `build/m05-site/`（静态网站）。CI 会将网站打包成 `csapp-m05-site-preview` 构建附件；本模块**不直接发布网站到 GitHub Pages**，正式发布仍由 M11 负责。

## 状态判定与证据

| 维度 | 取值 | 判断依据 |
| --- | --- | --- |
| 映射 | `topic_files`、`section_directory`、`unmapped` | M04 目录和现有文件核对 |
| 笔记 | `template`、`draft`、`reviewed` | 非模板正文存在与否；`reviewed` 必须有审核链接 |
| 代码 | `template`、`implemented`、`reviewed` | 是否存在非占位源码；审核必须有证据 |
| 测试 | `not_registered`、`registered`、`verified` | M02 的实际测试文件与已通过的 PR 证据 |

注意：`draft` 不代表讲解已经正确或完整；`implemented` 不代表可编译或通过测试。对于未逐一审核的 310 份笔记，本模块**不会自动标记为“讲解完成”**。未来某个知识点经审查以后，应在 `curriculum/reviews.json` 增加带 GitHub 审查依据的记录，再运行测试。

当前 6 个 `tests_verified` 条目对应已通过 CI 的 [M02 PR #2](https://github.com/1998x-stack/CSAPP/pull/2) 且能在 `tests/test_m02_examples.py` 找到实际测试。M05 的 CI 还会重新运行 M02 测试，避免只依赖历史结果。

## 生成方式和数据保护

`scripts/build_docs.py` 不修改原章节 Markdown、C++、Python 或 README；只有显式 `--generate` 才操作 `build/m05-docs/`。该目录必须存在专用的 `.m05-autogenerated` 标记，才能被工具重新生成；未标记的目录会拒绝覆盖。构建目录不会被提交 Git。

源笔记中的部分相对 Markdown 链接会转成原 GitHub 文件链接。原始笔记里仍可能存在失效的链接、缺失图片或未经审核的技术内容，这些问题需要后续 M05 维护/质量审查持续修复，不能视为已经解决。
