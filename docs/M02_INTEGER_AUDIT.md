# M02：第二章整数表示和运算示例正确性审计

本模块专注**已有实际实现的 C++ 示例**，不将空模板计入测试覆盖范围，也不尝试在本次 PR 内完成整个 CSAPP 第 2 章。

## 原始问题与改动

| 位置 | 原始问题 | 修复方式 |
| --- | --- | --- |
| 2.2.1 整数数据类型 | 直接计算 `int32_t` 最大值 +1 / 最小值 -1，导致有符号溢出未定义行为；`char` 类型展示可能输出字符 | 在 `int64_t` 中演示超范围的数学结果；统一将整数范围转换成可打印的整数值 |
| 2.2.3 补码编码 | 先进行越界有符号运算，再根据符号判断溢出 | 使用 `int64_t` 检测运算范围；用定义良好的 `uint32_t` 运算展示模 2^32 位模式 |
| 2.2.4 有符号与无符号转换 | 示例将 `UINT32_MAX` 转成超出范围的 `int`，C++17 中行为依赖实现；混合类型比较语义不直观 | 明确展示 16 位到无符号的转换；将数学意义上的 32 位补码解释用 `int64_t` 写清；将混合比较的无符号转换显式化 |
| 2.3.1 无符号加法 | 8 位溢出检查被提升到 `unsigned int`，错误地认定 200+100 不溢出 | 根据原类型的最大值检测；8 位结果使用定义良好的无符号缩窄转换，结果 44 |
| 2.3.2 补码加法 | 直接进行超范围有符号加法；8 位缩窄后的结果依赖实现；C++ 负余数与数学非负模混淆 | 在宽类型中计算；展示 8 位无符号位模式和数学解码；分别说明余数与非负模 |
| 2.3.3 补码求反 | 使用未声明的 `T`，造成编译失败；最小负数求负触发未定义行为 | 使用正确的模板参数；先检查最小值；宽类型求数学结果，无符号模运算展示位模式 |

## 验收

执行：

```bash
CXX=g++ python3 -m unittest discover -s tests -p 'test_m02_*.py' -v
CXX=clang++ python3 -m unittest discover -s tests -p 'test_m02_*.py' -v
```

测试会把六个示例分别编译为独立可执行程序，使用 `-std=c++17 -Wall -Wextra -Wpedantic -Werror -fsanitize=undefined -fno-sanitize-recover=all`，验证安全运行和关键边界输出。CI 在 Ubuntu 上分别使用 GCC 和 Clang 执行，不依赖 M01 的尚未合并代码。
