## 本地 GCC / Clang 验证

本批源码已在本地用 GCC 14.2 和 Clang 17.0 编译验证：C11、`-Wall -Wextra -Wpedantic -Werror`、UBSan，分别运行 4 项 CTest 均通过。另用 Clang 17 启用 AddressSanitizer + UBSan，4/4 通过。提交前逐个比对了 GitHub blob 哈希与本地 `git hash-object`，三份 C 源码及缓存 trace 完全一致。

本地独立实验构建目录在本次会话的运行容器中使用；提交仓库后，推荐从仓库根目录运行**集成验证**：

```bash
python3 scripts/audit_sources.py --check
python3 -m unittest discover -s tests -p 'test_m07_*.py' -v
cmake -S . -B build/m07 -DCMAKE_BUILD_TYPE=Debug -DCSAPP_ENABLE_UBSAN=ON
cmake --build build/m07 --parallel 2
ctest --test-dir build/m07 --output-on-failure
cmake -S . -B build/m07-opt -DCMAKE_BUILD_TYPE=Release
cmake --build build/m07-opt --target m07_ch05_loop
./build/m07-opt/m07_ch05_loop --bench
```

Linux CI 将在 GCC/Clang 两组工具链上重新执行集成构建、CTest、源码审计和之前模块的 Python 回归测试。性能实验 `--bench` 适合分析编译器/机器差异，不应用一次结果判断优化成功。

## 示例缓存轨迹

命令：

```bash
./build/m07/m07_ch06_cache --trace 06_内存层次结构/m07_cache_lru/trace_fixture.txt 1 1 2
```

预期输出：`hits:3 misses:4 evictions:2`。`s=1` 为集合索引位数，`E=1` 为每组行数，`b=2` 为块内偏移位数。模拟器拒绝跨块操作并限定本实验的数据规模；它不是 CSAPP Cache Lab 的完整替代。
