### 运行与验证

环境：Linux x86-64、CMake 3.20+、GCC 或 Clang、Python 3.9+、GNU binutils（`nm` / `objdump` / `readelf`）。其他平台会跳过专属 x86-64 汇编目标；`scripts/m06_inspect.py` 仅设计用于 ELF 工具链。

```bash
python3 scripts/audit_sources.py --check
python3 -m unittest discover -s tests -p 'test_m06_*.py' -v
cmake -S . -B build/m06 -DCMAKE_BUILD_TYPE=Debug -DCSAPP_ENABLE_UBSAN=ON
cmake --build build/m06 --parallel 2
ctest --test-dir build/m06 --output-on-failure
python3 scripts/m06_inspect.py
python3 -m unittest discover -s tests -v
```

上面输出目录都位于被 `.gitignore` 排除的 `build/`。审计工具和测试不覆盖或重命名现有章节文件。

### GDB 调试、机器级观察

构建完成后，在 x86-64 Linux 上执行：

```bash
objdump -d build/m06/m06_ch03_abi | less
readelf -h build/m06/m06_ch03_abi
nm -g build/m06/m06_ch03_abi | grep csapp_m06
gdb -q build/m06/m06_ch03_abi
```

在 GDB 交互终端中可以使用 `break csapp_m06_sum3`、`run`、`info registers rdi rsi rdx rax`、`x/8i $pc`、`stepi`，观察参数传递及指令执行。运行结果依赖 System V AMD64 ABI，不适用于 Windows x64 的不同调用约定。

### 正确性限制

- `pipeline.c` 的有符号加法只测试数学结果位于 int64_t 有效范围之内的输入，不声称可以处理越界加法。
- `bit_demo.c` 依赖 CHAR_BIT=8、32 位整数、二进制补码位表示；非该平台明确返回 SKIP。
- `float_demo.c` 只在 binary32 格式符合 C 的相关常量检查时分析 float 位模式，不把不支持的平台悄悄当成 IEEE binary32。
- `abi_x86_64.S` 用 x86-64 的有符号比较与无溢出范围内的加法，示例用于理解 ABI，不是安全边界或溢出保护接口。
